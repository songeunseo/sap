# 집필과 증거를 함께 관리하는 규칙

## 연구 질문

DLM pruning에서 개별 상태의 출력 보존에 더해, 문맥이 공개될 때의 출력 변화까지 보존하는 것이 성능에 도움이 되는가?

현재 범위는 기존 scalar A+C 계열의 고정 마스크 비교다. 특정 결론을 유지하기 위해 readout, bank, allocation, 평가 표본을 변경하지 않는다.

## 작업 순서

| 단계 | 지금 할 일 | 종료 조건 |
|---|---|---|
| 현재 실험 | 기존 네 후보 full 평가 계속 | controller complete, 모든 결과·receipt 존재 |
| 준비 | 방법·동기·제약을 본문으로 쓰고 주장별 근거 연결 | 미측정 결과가 명확한 paper source와 claim map |
| 완료 검증 | 결과 수·해시·문항·통계·과거 답변·비용 확인 | 검증 성공 또는 실패 원인이 기록됨 |
| 초고 v0 | 검증된 수치와 제한적인 결과 해석 반영 | 결과의 정확한 출처가 있는 내부 초고 |
| 후속 결정 | 논문의 가장 중요한 미확인 주장을 선택 | 목적·대조·비용·종료 조건을 갖춘 다음 실험안 |

후속 실험안 작성과 실제 실행은 구분한다. 이번 승인은 기존 실험 마무리와 집필 전환에 해당한다.

## 근거의 위치

- Obsidian: 연구 이력, 결정, 수정된 해석. 기존 연구 메모리 체계를 유지한다.
- 원본 JSON/문항별 checkpoint: 관측값의 기준. 초고 문장이 원본 수치를 덮어쓰지 않는다.
- `closeout.json`: 원본 경로·SHA와 검증·파생 통계.
- `paper.template.md`: 현재 연구를 설명하는 본문. 자동 결과 삽입 위치 외의 집필은 여기에서 한다.
- `claim-map.md`: 가설, 이미 확보된 증거, 반증 가능성, 아직 필요한 증거.

## 집필 기준: Writing a good scientific paper

주된 편집 기준은 사용자가 다시 지정한 [Writing a good scientific paper.md](</home/tmluser1/.codex/attachments/0e37c59b-ba95-4b1a-854b-8efec235c12c/Writing a good scientific paper.md>)다. 문서의 조언은 논문 구성과 문장 개선에 적용하며, 운영 권한이나 실험 조건으로 승격하지 않는다.

- 핵심 통찰: 평균 예측 오차가 같아도 문맥 변화에 대한 반응 오차는 다를 수 있다.
- 서론: 목표 → 해결해야 할 문제 → 통찰과 쉬운 예시 → 방법 → 검증할 주장 순서로 쓴다.
- 설명: 먼저 직관을 말하고, 동일 개념을 수식과 그림으로 연결한다. 그림은 독립적으로 읽을 수 있는 축·단위·캡션을 갖춘다.
- 선행연구: 가중치 선택·할당, DLM 보정, 반응 보존으로 묶고 각 연구가 해결한 문제와 현재 질문의 관계를 설명한다.
- 결과: 구성 예시, 가설, 관측 결과를 명시한다. 실험 후에는 초록과 결론을 실제 효과 및 불확실성에 맞게 다시 쓴다.
- 최종 점검: 첫 독자가 통찰과 검증 질문을 이해할 수 있는지, 모든 문단이 그 질문에 필요한지 확인한다.

## 집필

1. 한 문단이 무엇을 설명하고 어떤 주장에 필요한지 먼저 정한다.
2. 수식·알고리즘·설정은 실제 실행 코드와 일치시킨다. 계획 단계와 실행 단계의 차이는 기록한다.
3. 미측정 수치 대신 `[미측정]`, 미검증 주장 대신 `[가설]`을 사용한다. 예상 점수로 표를 채우지 않는다.
4. 결과가 없더라도 동기, 방법, 평가 설계, 한계는 문장으로 작성한다.
5. 효과 추정치, 불확실성, 표본, 비교군을 함께 쓴다. 유의하지 않음을 동등성의 증거로 바꾸지 않는다.
6. 실패·무효·반대 결과를 보존한다. 제외한 실험은 이유를 기록한다.
7. 수치가 일치하는지와 그 수치가 주장을 뒷받침하는지는 별도로 검토한다.
8. 문헌의 존재 확인과 가까운 주장에 대한 지지 여부를 구분한다. 초기 초고의 제한적인 문헌 검토로 최초·최고를 주장하지 않는다.

## 역할

현재는 한 에이전트가 단계별 책임을 구분해 진행한다. 실험 결과 생성, 결과 감사, 집필의 산출물을 분리한다. 별도 에이전트나 새 Codex task는 이번에 생성하지 않는다. 필요할 때 독립 검토 범위를 정한다.

## 연구 단계별 검토

3시간 또는 고정 쪽수 제한을 두지 않는다. 각 실험은 다음을 시작 전에 기록한다: 바뀔 결정, 비교군, 실행 조건, 주 평가, 허용 비용, 종료 기준, 결과가 모호할 때의 처리. 현재 실험의 사전 고정 조건을 이 문서로 소급 변경하지 않는다.

NELBO와 downstream capability는 서로 다른 평가다. NELBO 개선을 downstream 실행의 일반적인 필수조건으로 두지 않는다. DLM에만 적용되는 수학이나 모든 상호작용의 규명을 방법론 기여의 무조건 필수조건으로 두지 않는다.
