# 실험 실행 전 확인서

이 양식을 실험 디렉터리의 `preflight.md`로 복사한다. 기존 계획서에 해당 정보가
있으면 근거 경로를 연결한다. 빈칸과 `미확인`은 통과가 아니다. 해당 없는 항목은
이유를 적는다. 확인서는 에이전트가 작성하며 사용자에게 양식 작성을 요구하지 않는다.

## 1. 질문과 현재 단계

- 실험 ID / 확인서 버전 / 작성 시각:
- 사용자 승인 범위와 근거:
- 단계: 준비 / 측정 파일럿 / 통제 비교 / 최종 확인
- 질문과 가설:
- 의도적으로 바꾸는 변수:
- 이번 실험에서 결론 내릴 수 있는 범위:
- 관련 Research-State 및 기존 실험/정정 노트:

## 2. 비교군별 실제 조건

비교군이 더 있으면 열을 추가한다. `같음`이라고만 쓰지 말고 실제 값이나 검증된
공유 manifest를 적는다. 과거 결과도 같은 방식으로 확인한다.

| 항목 | 기준군 | 후보군 | 의도한 차이 / 일치 확인 근거 |
|---|---|---|---|
| 모델·revision·tokenizer | | | |
| calibration 원문 ID·split·seed | | | |
| span 수·길이·token 수 | | | |
| clean/corrupted·mask·timestep·state 수 | | | |
| 독립 calibration 반복 수·원문 중복 여부 | | | |
| activation 수집: dense one-shot/native sparse-prefix | | | |
| ranking 출처·코드·입력 해시 | | | |
| 배분 단위와 mapping/폭 | | | |
| pruning 범위·정확한 weight 예산·mask 해시 | | | |
| 평가 문항 ID·split·노출 이력·표본 수 | | | |
| 평가 metric·MC draws·seed·구현 | | | |
| decoding·few-shot·길이·steps·batch·dtype | | | |
| 답 추출·채점 코드·버전 | | | |

- 비교 목적: 특정 요소의 효과 / 전체 파이프라인 성능
- 의도하지 않은 차이와 처리 방법:
- 기존 캐시 재사용 시 identity/parity 확인 근거:
- 아직 없는 결과나 mask: 생성 단계와 확인 시점(생성 전 파일을 검증했다고 쓰지 않는다):

## 3. 단계별 통과 근거

각 단계의 판정은 `통과 / 미통과 / 미확인 / 해당 없음(이유)` 중 하나다.
파일럿의 신뢰도 결과는 실행 후 채울 수 있으나, 이를 요구하는 후속 단계는
그 결과가 확인되기 전 시작하지 않는다.

| 검사 | 판정 | 실행한 명령·결과 경로·해시 또는 미해결 이유 |
|---|---|---|
| 비교 조건과 승인 범위 확인 | | |
| 작은 사례에서 측정/통계 구현 확인 | | |
| 예산·ranking·mask 무결성 확인 | | |
| 동일 조건 baseline 재현 | | |
| 독립 원문 묶음에서 probe 신뢰도 | | |
| calibration 반복에서 배분 안정성·방법 간/내 변동 | | |
| 목표 proxy를 실제로 바꾸는지 확인 | | |
| allocation이면 MTH-006 적용 항목·편차 | | |

수치가 재현된 사실과 과학적 해석이 지지되는지를 구분한다. 다른 calibration이나
단위에서 통과한 파일럿을 그대로 전용할 경우 적용 가능성의 근거가 필요하다.

## 4. 결과를 보기 전에 정하는 분석

- 1차 metric과 비교 목록:
- 보조 metric과 비교 목록:
- 실제 의미가 있는 최소 효과와 선택 이유:
- paired/cluster 분석 단위와 불확실성 추정법:
- 다중비교 보정과 비교군의 범위:
- calibration 반복 계획과 평가 문항 변동의 구분:
- permutation 대조를 쓰는 경우 횟수·검정법·가능한 최소 p-value:
- 개발/최종 확인 구분, 중복·노출 검사:
- 중단·다음 단계 진행 조건:
- 불확실한 결과에서 허용되는 결론:

고정된 mini/full 검출 한계나 적은 permutation의 분위수를 자동으로 유효한
유의성 근거로 사용하지 않는다. 선택한 절차가 주장하려는 정밀도를 지원하는지 확인한다.

## 5. 실행 계획과 최종 판정

- 실행 명령 / 코드·config·입력 해시:
- GPU / tmux / 중복 실행 확인:
- 예상 시간·forward 수·총 비용 범위(재사용 비용과 새 비용 구분):
- 로그·결과·원본 보존 경로:
- 실패·재시작 시 비용 및 변경 이력 기록 방법:
- Obsidian 실험 노트 경로와 시작 기록:
- 이번 단계 판정: 실행 가능 / 실행 보류
- 판정 근거와 미해결 항목:
- 사용자에게 알린 조건과 시각:

실행 보류는 미해결 조건이 필요한 단계에 적용한다. 승인된 범위의 원인 조사와
수정 준비는 계속한다. 탐색 실험의 편차는 기록하되 확인 실험 통과로 바꾸지 않는다.

## 규칙의 적용 방식

이 확인서는 저장소 `AGENTS.md`의 필수 실험 제약을 실행별로 기록하는 양식이다.
이는 Codex에 주는 지속 지침이며, 셸이나 GPU 실행을 기술적으로 차단하는 프로그램은 아니다.
Codex가 프로젝트 지침을 읽는 방식은 [OpenAI 공식 문서](https://learn.chatgpt.com/docs/agent-configuration/agents-md)를 따른다.
