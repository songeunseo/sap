# Multi 배분 안정화·범위 축소 후속 실험 분석

## 결론

이번 mini-100에서는 기존 Multi 63점이 가장 높았다. Multi-Bag 58, R2 59, R3.5 60점으로, 세 개선안 모두 개선에 실패했다. 같은 방향으로 calibration과 diagnostic의 Multi 목적함수도 악화했다. 기존 Multi를 기준으로 유지하고, 이번 세 후보로 교체할 근거는 없다. 다만 100문항의 반복 사용이므로 세 후보의 일반적 열등성이나 기존 Multi의 일반적 우월성을 확정하지 않는다.

## 설정과 검증

모두 같은 LLaDA revision/BF16, 기존 Wanda 순위와 activation, 32블록 배분 및 7projection 연결, 5-shot/256생성토큰/256denoising steps/temperature0/strict-match/문항ID0–99를 사용했다. 전체 제거 weight는 모두 3,489,660,928 / 6,979,321,856으로 정확히50%다. Bag은8calibration spans를200회공동재표집해 rank-mapped rates를 평균한다. R2와R3.5는 기존Multi의50%대비 편차를 각각0.4배,0.7배로 줄인다.

분석 시 frozen source validation과 세 완료 receipt 검증을 새로 통과했다. 완료 검증은 실제 mask files, 문항 checkpoint와 aggregate 결과, raw readout에서 재계산한 diagnostic을 확인한다. 별도 분석에서도100개ID의 유일성과 순서, prompt/doc/target/evaluation hashes 일치, 총점 및 exact McNemar p 재계산을 확인했다. 새로운GPU실험은 실행하지 않았다.

원본: experiments/dlm_multi_followup50/output/report.json. 분석 스크립트: analyze.py. 입력 해시: sources.json. 숫자 전체: analysis.json. 문항별 정오표: question_comparison.csv. 정오가 달라진 모든 문항의 원문·생성문: changed_questions.md.

## 2. 목적함수도 악화

목적함수는 L=A+(C1+C2+C4)/3이며 모든 항은 작을수록 좋다. calibration은 배분에 사용한8spans, diagnostic은 별도8spans다. diagnostic은 이미 반복 사용한 개발 근거이며 최종 독립검증으로 간주하지 않는다.

| 후보 | calibration L | Multi대비 | diagnostic L | Multi대비 |
|---|---:|---:|---:|---:|
| Multi |1.458162|—|1.307275|—|
| Bag |1.541015|+5.68%|1.369997|+4.80%|
| R2 |1.612711|+10.60%|1.383832|+5.86%|
| R3.5 |1.516330|+3.99%|1.360610|+4.08%|

진단용 8개 span 중 L이 개선된 수는 Bag 3/8, R2 2/8, R3.5 4/8이다. R3.5는 절반에서 개선되므로 모든 문서에 걸친 악화로 표현하면 안 된다. Calibration 개선 수는 각각 2/8, 1/8, 3/8이다.

이번 결과는 학습 proxy만 좋아지고 task가 나빠진 상황에 해당하지 않는다. 최종 sparse 모델의 proxy부터 나빠졌다. 이는 이번 배분 변경의 근거를 약화하지만, proxy와task의 일반적 상관이나 인과관계를 입증하지는 않는다. Bag은 R2보다 diagnostic L이 낮지만 task는1점낮아 세부 순서까지 일치하지 않는다.

같은bank의 Uniform diagnostic L은1.421379다. 세후보는 여전히 그보다 낮지만, Uniform→Multi에서 얻은 목적함수 감소 중 Bag55.0%, R2 67.1%, R3.5 46.7%를 되돌렸다. 이는 목적함수 차이의 산술 분해이고 task성능의 인과기여율이 아니다.

## 3. 어느 항에서 나빠졌나

| 후보 | diagnostic A | C1 | C2 | C4 |
|---|---:|---:|---:|---:|
| Multi |0.609683|0.549325|0.642299|0.901151|
| Bag |0.641011|0.550923|0.672973|0.963064|
| R2 |0.648403|0.534075|0.681046|0.991167|
| R3.5 |0.632486|0.538966|0.669270|0.976136|

R2/R3.5의 C1은2.78%/1.89%개선됐지만 A는6.35%/3.74%, C4는9.99%/8.32%악화했다. Diagnostic C4는 Bag과R2가7/8spans, R3.5가6/8spans에서 악화했다. L악화의 산술분해에서 A기여는43–51%, C4/3기여는33–47%다.

해석: 이번 축소는 짧은 문맥 변화 오차를 일부 줄여도 endpoint와 더 긴 문맥 변화 보존을 희생했다. C4는 공개 진행 상태쌍의 간격을 뜻한다. 모델의 후반 layer 자체를 뜻하지 않는다. 이 관측으로 C4 항의 GSM8K 인과적 필요성이나 특정 layer가 원인임을 확정할 수 없다.

부가 지표인 diagnostic response sign-flip rate는 Multi 7.45%, Bag 7.28%, R2 7.11%, R3.5 7.17%로 오히려 낮아졌다. 이 보조 지표 하나만으로 성공을 판정하면 잘못된 결론에 이른다. Diagnostic query CE는 3.18777→3.19632/3.19951/3.19234로 소폭 악화했다. 이는 저장된 query의 CE이며 전체 NELBO/PPL 측정이 아니다.

## 4. 실제 배분 변화의 의미

| 후보 | 이상적 배분 범위 | 기존Multi 대비 평균 절대 변경 | 고정순위의 nested masks에서 row-count로 계산한 전체weight XOR |
|---|---:|---:|---:|
| Multi |45–55%|—|—|
| Bag |45.858–53.700%|0.879%p|0.8802%|
| R2 |48–52%|1.548%p|1.5498%|
| R3.5 |46.5–53.5%|0.774%p|0.7748%|

XOR는 각 row에서 동일한 Wanda 순위를 사용한다는 조건 아래 `Σ out × |Δcount|`로 계산했다. Packed mask의 bitwise XOR를 별도로 측정한 값은 아니다. 세 후보 모두 224개 projection의 quota가 변했다. Integer DP의 반올림을 반영한 실제 범위는 Bag 45.8496–53.7109%, R2 47.9980–52.0020%, R3.5 46.5007–53.4993%다.

Bag도 대부분 50% 쪽으로 수축했다. 기존 Multi의 50% 대비 편차에 가장 잘 맞는 스칼라 배율은 0.693이며, R3.5의 0.7과 가깝다. 하지만 단순 수축으로 설명되지 않는 차이의 RMS가 0.370%p여서 동일한 방법은 아니다. 이번 결과에서 bootstrap만의 효과와 배분 축소 효과를 분리할 수 없다.

예를 들어 Bag은 block 28을 46.29→48.19%, block 22를 46.61→48.33%로 더 prune했고, block 13은 54.68→53.28%로 덜 prune했다. 기존 배분의 블록 간 차이를 완화한 셈이다. 어느 블록의 변화가 점수 하락을 만들었는지는 개입 실험 없이 알 수 없다.

## 5. 생성문에서 보이는 실패와 성공

전체 strict-invalid는 Multi 2개, Bag 4개, R2/R3.5 각 5개다. 기존 정답에서 새 오답으로 변한 문항 중 strict-invalid는 Bag 3/8, R2 2/7, R3.5 3/7이고, 나머지는 답이 추출됐으나 틀렸다. strict-invalid 자체가 항상 단순 형식 오류를 뜻하지는 않는다.

- ID 5, 유리컵 격개 할인: Multi는 8개 정상가 + 8개 할인가로 64달러를 낸다. 세 새 후보는 할인을 매번 누적하는 것으로 잘못 해석해 5→3→1.8→1.08…을 이어가다 잘린다. 문제 해석 실패와 출력 길이 초과가 겹쳤다.
- ID 84, 22경기 중 승리가 패배보다 8 많음: 정답은 15다. Bag은 잘못된 식을 반복하다 정답을 완성하지 못하고, R2/R3.5는 각각 6/4라고 답한다. Multi는 최종 15를 맞혔지만 중간 식에도 오류가 있다. 정답 여부만으로 완전한 추론 정확성을 보장하지 않는다.
- ID 90, 음식 양 225: 세 후보 모두 200과 25를 계산한다. R3.5는 본문에서 225까지 도출하지만 최종 문장이 잘리고 엄격 채점 답을 완성하지 못한다. 모든 실점을 산술 능력 저하라고 분류하면 안 된다. 생성 길이는 모두 256으로 동일했다.
- 공통 획득 ID 9, 초과근무 수당: Multi는 기본급 400달러를 40으로 처리해 100이라고 답했다. 세 후보는 400+60=460을 맞혔다. 새 후보가 모든 문항에서 나빠진 것은 아니다.

생성문 검토는 관측된 출력의 오류 유형을 설명한다. 내부 denoising 경로나 회로 변화를 확인한 실험은 아니다.

## 6. 계산량과 다음 판단

병렬 벽시계 시간은 37.60분, 세 worker 시간의 합은 1.83 GPU시간, peak allocated CUDA memory는 각각 16.62GiB였다. 각 후보의 새 forward는 25,856회 = calibration 128 + diagnostic 128 + generation 25,600이다. 총 77,568회이며 중단·재시도나 미집계 attempt는 없다. 마스크 생성은 42–44초, 두 bank 측정은 합계 약 9초, GSM8K는 각각 34.2–35.1분이었다. 기존 probe와 teacher 생성 비용은 재사용한 과거 비용이라 이번 증분 시간에 포함되지 않는다.

현재는 원래 Multi를 기준 후보로 유지한다. 이번 bank와 배분 방식에서 bootstrap 평균이나 수축을 하면 좋아질 것이라는 기대는 지지받지 못했다. 이를 모든 불확실성 처리, 모든 trust-region 방법, 혹은 A+C 전체의 기각으로 확대하지 않는다.

다음 권고는 같은 100문항에서 범위 값을 더 찾기보다, 새로 고정한 별도 mini-100에서 기존 Multi/A-only/동일 계열 Uniform을 비교해 C의 추가 가치와 재현성을 확인하는 것이다. Bootstrap의 기여를 분해하려면 전체 편차 크기를 맞춘 비교를 별도 설계해야 한다. 어느 실험도 자동 실행하지 않았다.
